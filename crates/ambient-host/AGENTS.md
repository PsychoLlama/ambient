# ambient-host

What loads and runs a compiled program, with no compiler in it. The root `AGENTS.md` holds what spans crates; bullets name modules as `ambient` gives them again (`ambient::core`, `backend::native`, `host`).

## Invariants

- An entry point a native bundle may call is listed in `ambient_native::entries!`, and a test in `native/bundle.rs` holds each to the signature listed. The layout number (`parts/encode.rs`) is `ambient_native::LAYOUT`.
- Native code reaches its program only through `native::Running`, which each backend's dispatch implements. What it loads is held until its result is encoded, so nothing of the program is borrowed while it runs.
- Native code calls back through `Running::call`, only a function read for the call it is in (`value::Live`): a decoded function is a copy that lost its cells and handlers. The runtime entry is `amb_call_among`, or `amb_call_back` in a program linked without suspension.
- A native bundle's function is the one native code that is not handed copies (`native/bundle.rs`, `Natives::bundled`): it takes the call it is in and its arguments as words, reads and makes values through the runtime's entry points, and asks the host only what a host knows, through `amb_bundle_*`. The native dispatch decodes for it only what a run that keeps its trace observes; no other backend runs one.
- A bundle is told of a dropped handle where a host is (`Program::heard`), for the brands it named with `amb_bundle_dropping`; what it is called with is a number, and it touches no value.
- A thread a native bundle keeps answers a wait only through `native/posts.rs`: it posts what makes the answer, and `Program::schedule` makes it on the program's thread. A ticket handed to a bundle is a number no other program of the process has. A host that blocks in `Waits::next` takes the posts (`Waits::attend`) and returns nothing once one is in, as `host/pending.rs` does.
- What needs a world is the `system` package (`system/`, `docs/spec/targets.md`), installed beside the library; `ambient` holds nothing that does. The command-line target is `system.cli` (`system/lib.ab`); its native side is `host/`, where every handler goes through `host::World`, and one that takes time begins `host::Work` and is answered later. The real process waits on threads that send what they got (`host/pending.rs`, `host/network.rs`); only the program's thread touches a value. Tests run programs over `support::scripted::Scripted`, never the real process.
- All of the native side of `system.cli` is in groups (`host/linked.rs`, `GROUPS`), about one to a module: a program pays for the native code it uses. A group's handlers, and what makes its state, are reached only through the function a link's `main` names; native code that is new joins a group or adds one, and nothing else offers a handler (`tests/build.rs` holds this).
- What a group keeps for a real process is made by its link function and held by `host/pending.rs` behind a trait (`linked::Http`, `linked::Watching`), and what a thread sends (`Sent`) holds no type of a group. Commands, input, sockets, signals, and timers are still `Pending`'s own, in every executable: put one behind a trait before adding to it.
- The platform programs are for (`native::MACHINE`) is `platform.rs`'s to say, for this crate's build script and the one that builds the launcher: a command linked with musl still makes programs for glibc.
- A stream is whatever reads and maybe writes (`host/streams.rs`, `Halves`): a thread each reads and writes when asked, and what was read for a task that left is kept for the next. A connection, an accepted one, and anything else that arrives in pieces is made a stream by `Streams::add`; nothing else reads on the program's thread's behalf.
- What is asked of a stream or a socket is one `Work::Reach`, and what the world opens or lets go without waiting is `World::open` and `World::shut`: a new kind of thing a program holds adds a case to those, not a method to `World`.
- What the world brings a program unasked (a connection, a datagram, a change to a file) is held in a `host/queue.rs` `Queue`, bounded by `HELD`; a signal is told once per kind. Each is taken by a task that waits, never handed to a function.
- A request that trusts other than the world does is sent by an agent of its own, kept by what it trusts (`host/trust.rs`). Nothing there turns checking off: roots replace the world's, an address says only where to connect, and a pin holds the server to one certificate (`host/pinned.rs`), whose key it must still prove it holds.
- `system.code` is native code over an engine with an empty workspace (`host/code.rs`): a pack leaves nothing out, so compiling one needs nothing else. It compiles for the backend `Running::backend` names (`backend::named`), and what `code.load` takes is `Parts::encode`. Loading is the host crate's; packing and compiling need the compiler, and are added to its handlers (`host::compiling`).
- An executable is a launcher with a program after it (`launch::Built`): encoded parts, the names and places a report takes (`launch::Frames`), a length, and a mark. A launcher looks for the mark in its own file as it starts (`launch::own`); `launch::started` is the one way a compiled program is run and reported, built or not.
- A definition holds its own hash (`DEFINITION_HASH`), so a host reads a function value as a hash and captures (`value.rs`), and makes one of a definition the program has (`native::Inside`); what it captures is trusted.
- A native `Program` is units: each `Program::add` lays out a block (`statics::plan` with a `Base`) that refers to what the program already has by address. `Engine::link_to_load` makes the parts.
- `statics::plan` names a part's root or definition (`Field::Root`, `Field::Definition`) and an extern (`Field::Native`) without saying where; each loader resolves them.
- `Parts::encode` is compiled code for a host with no compiler (`ambient-host/src/parts/encode.rs`), refused by another backend, format, or build of the host. Bump its `FORMAT` when `Parts`, a layout, the calling convention, or a runtime entry changes.
- A value has one encoding (`exchange.rs`); `decode` accepts only what `encode` produces. A host sees inside an iterator (`value::Source`), and only one that keeps what its source keeps (`Source::keeps`) is decoded or made in a program: the runtime steps without looking.
- `core::Tree::resolved` defines every hash: the tree's encoding with slots replaced by hashes and unions ordered by that. `Tree::encode` is the stored form, which names can order; never hash it. Changing either or the node set means bumping `FORMAT`.
- A constant's value is laid out in its block by `statics/values.rs`, as objects the runtime says the layout of (`ambient_runtime::Fixed`), and its part's root is one word that holds the value. A record is listed in `Statics::settle`, and each loader calls `amb_record_settle` on it once the block's keys are made.
- `core::Expr::is_value_form` (`core/constant.rs`) is the one rule for what a constant's value may be: decoding parts holds to it, and what lays a value out reads those forms and no other.
